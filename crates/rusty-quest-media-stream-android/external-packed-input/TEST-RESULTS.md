# Source-only checks

The maintained runner passes three actual Java host programs:12 acquisition/copy ownership cases,4 original reader/worker retirement cases, and the fixed v2 snapshot/generation/no-final-render-status suite. Strict Java8 pure compilation and Android34 API compilation both pass with `-Xlint:all -Werror`. The exact external eight-file Lab source dependency is verified before compilation; unchanged Lab suites are not rerun.

Tests were written before their new implementation. Initial compiler RED output includes the absent new provider types (the first bootstrap invocation also omitted external sink classes); subsequent retirement and v2 RED invocations used the already compiled dependency context and failed on the missing new subject classes. Green tests execute the real new production queue/retirement code and real existing SinkAdmission, not a mirrored success stub. This is new-feature TDD evidence, not an assertion that a previous production lifecycle was repaired.

Cases include bounded latest displacement, claimed image retention, stale generation, held original copy and duplicate borrow, nonblocking stop with copy retention, sealed late callbacks, real stop-time draining tickets, unknown fence/import and close quarantine, invalid actual timestamp, an actual blocked acquisition/seal thread race, strictly newer generation only after existing reducer retirement, exact original barrier/join/reader close ordering, unknown post no replay, failed close no terminal claim, and copied input distinct from final renderer status.

The Android adapter is typed against actual Android34 ImageReader/Image/HardwareBuffer/HandlerThread/Surface APIs. No Android framework methods, device, native GPU/capture operations, SDK binary, APK/Gradle/Cargo build or network operation are executed. Physical ImageReader callback behavior, vendor binary fence semantics, Surface transport, JNI integration, actual import/copy/fences, no-save composition, SDK exclusion and final rendering remain unqualified. The compatibility wrapper deliberately returns null final-render status. No Ready, rawLive, optical calibration, capture pose, clock correlation or vendor retirement ACK follows from these checks.

# Generic visual showcase composition

`ui.visual_showcase` is an explicit opt-in composition. The native owner exposes
the closed `rusty.quest.visual_showcase.*.v1` command/status/receipt schemas and
is the only settings authority. The Android view and authenticated local adapter
submit the same revisioned commands. Visual defaults and schema are app-owned
assets, `showcase-default-visual.json` and `showcase-visual-schema.json`; the
public module contains no downstream defaults or effect formulas.

The ordinary native triple-B gesture opens the panel. While the Android panel
owns focus, it consumes B down/up events and closes after three complete presses.
Its window reads the same packaged native setting: five seconds by default,
bounded to0.25–30seconds. Repeats and orphan releases do not count; focus changes,
resume and pause reset the sequence. Android delivery on a physical headset still
requires attended validation.

The builder selects Cargo `showcase`, derives the ordinary breath-composition
and bounded-driver activation bindings from the exact feature/app inputs, and
uses a separate minimal Java facade. Existing experiment compositions are
unchanged. Do not select their panel, sensor receiver, session or audio features
as a dependency shortcut.

`tools/produce_showcase_java.py` projects maintained Polar acquisition and RQG1
sources. Its guarded transformation removes capture UI, commands, JNI routes and
methods, persistent sensor/diagnostic sinks, and experiment monitor/export
actions from the **selected Java source**. It retains acquisition, current
observations, recovery, manual management and authenticated original receipts.
Its `projection.json` binds original and generated bytes and enters the APK.
New unmatched sink shapes fail the negative source tests; no runtime toggle
substitutes for selected-source exclusion. APK/DEX/JNI inspection remains a
separate mandatory packaging check.

Phone control starts disabled and requires an explicit native consent command;
its preference may persist. Enabled native and phone controls are concurrent.
Discovery uses the `9a7b2101-7d6a-4b7f-9d4a-6f7c0a020101` service and the
corresponding `020102` serial / `020103` metadata characteristics. The serial is
actual hardware identity or unavailable, never a generated app ID. The stable
app-owned device ID is a distinct field. Local HTTP is private IPv4 port8767,
`/v1/gateway`; authenticated RQG1 provides integrity, not confidentiality.
Discovery, GET identity, local join and authenticated status bind product
`visual-showcase` plus native/gateway lifetimes.

The app-owned `showcase-controller-origins.json` contains an exact bounded HTTPS
origin allowlist (`{"origins":[...]}`), with no wildcard or inferred deployment.
Source, package and origin selection do not authorize publication or DNS work.

Only the native allowlisted settings projection is persisted. Credentials,
receipts and sensor observations remain memory-only. A quiet100ms system-volume
cue repeats at most every3s while a selected Polar stream is unavailable; suspend
and shutdown remove callbacks and release the tone generator. Native runtime,
not this Java timer, advances automatic breathing.

Source-only checks (no compiler):

```text
python -B tools/checks/test_showcase_java_projection.py
```

These checks do not establish Android compilation, installed PWA/network
permissions, headset input, Polar data, cue perception or rendering performance.

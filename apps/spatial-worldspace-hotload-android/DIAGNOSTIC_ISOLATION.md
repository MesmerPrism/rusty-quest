# Diagnostic presentation isolation

Debug `diagnostic-isolation on|off` suppresses legacy barcode drawing with kind2 `transportFlags.z=2` and hides every ordinary workload topology slot with `SceneObject.setIsVisible`. The carrier stays registered and visible, preserving its Surface ownership. It retains the exact legacy material handle, ordinary object handles and baseline requested enable/visibility intent, including inactive cached slots, for explicit restoration. Kind2 restores its existing host-geometry0/1 flag; other material kinds never receive2. The atlas diagnostic grid, two public compute billboards, depth-reference object, SDK interaction visuals and UI are outside that target list. Hide the depth reference separately with the existing `occluder false` control when needed.

The command changes one existing material flag and ordinary object visibility only. It changes no producer configuration, shader binary, texture, simulation, kernel, topology, host transform or bounds. The added shader branch preserves the existing80B interface and maps suppressed barcode vertices to drawable0, which the existing fragment shader discards. Continued Surface freshness is not inferred from keeping the carrier visible: live producer status, independently decoded frame tokens and captured pixels must verify continued transport. Setter return is not SDK visibility readback or presentation proof.

Entry requires a resumed live GPU owner, certain settled topology, off/certain fixtures, identity bounds with culling off, and no measurement. During isolation (including uncertain partial setter results), topology/configuration/fixture/measurement changes and source switches are blocked. Diagnostic page/profile, public compute controls and the depth-reference visibility control remain available. Stop/lifecycle retirement is always available. After pause/stop, restore isolation explicitly before restarting the producer.

`diagnosticIsolation` status distinguishes requested isolation, phase, revision, owner binding, exact typed material/object handles, original requested enable/visibility intent, last requested intent, and whether each setter returned. A throwing setter is unknown, not known unchanged. No automatic retry or rollback occurs. Explicit `off` restores all retained material/object targets; any failure keeps changes blocked. Quarantined topology cannot be restored. Normal teardown invalidates records and releases callbacks without touching SDK objects.

Use the existing debug DUMP plus shell-UID provider with method `diagnostic-isolation` and argument `on` or `off`. Status-only reads do not dispatch setters. Confirm the actual actor/APK/session and take before/after snapshots. Accept isolation only after observing clear grid pixels and unchanged native producer/kernel/configuration identity with advancing publication. Confirm explicit restoration separately. This control does not close the wearer session.

# Opt-in live BLE observation barrier

This is a bounded coordination observation, not a DirectLaneLease or media grant.
The prerequisite source is the guarded Pair implementation and the published v2 observed BLE implementation; neither predecessor alone provides this interface.

Without `require_live_ble_observation=true`, Pair keeps its existing topology/echo path and five-second echo launch reserve35s. Enabled mode requires the same independently owner-validated current topology authorization and reserves45s: formation20s, postformation barrier10s, echo5s, cleanup10s. Echo remains independently bounded; the owner60s and Guardian180s caps never increase. An unavailable observation, provider deadline, stale group or expired authority fails closed into the existing exact owned cleanup, including after authorization expiry. The10s barrier starts at the actual owned formed group callback, so Android network selection consumes that interval too.

Parent orchestration must prepare both APK/source/installed-body/signer/permission and Guardian/owner prerequisites first. Pair extras also close `ble_run_id`, `ble_local_peer_tag`, `ble_expected_peer_tag`, `ble_expected_remote_boot_tag`, `ble_coordination_epoch`; session is the guard run token. Only actual two serial-scoped boot observations supply expected boot tags. Launch the existing BLE activity after actual complementary group formation with observed_coordination_v2 and live_observation_provider enabled, the same session/epoch/tags and actual complementary roles. Secrets remain solely within the existing HMAC BLE channel. No hint or retained v1/v2 receipt substitutes for current observation.

The new signature-protected provider serves only `read-current` with five identity selection fields. It allows the exact Pair package, same signer, signature permission; it exposes no mutation, arbitrary URI, command, key, HMAC secret or persisted receipt read. An unbound/restarted/stopped process serves no accepted state. Actual GATT HMAC/session/epoch/nonce challenge validation publishes in-process state; disconnect, stop/supersession or conflicting/unavailable current local observation invalidates it. Consumption requires both actual local sampling and authenticated handshake age<=5s, observed complementary roles, current boot/group and owner/local IP. The group tag is the existing SHA256 truncation over session/network/actual ownerIP/unredacted ownerMAC, not a declared MAC hint.

In this opt-in producer mode only, the client holds its first authenticated connection for the remaining declared total monotonic duration (at most10s, including setup and every operation wait), then existing finally cleanup. Ordinary absent-opt-in two-exchange/reconnect behavior remains. Server lifetime is likewise at most10s including observation setup. This diagnostic cannot guarantee that advertising/scan/GATT/Android callbacks finish within the authority interval; unavailable stays unavailable.

Pair queries are bounded2s and the wait is bounded10s. It joins the producer result to its current independent topology callback, boot, ownerMAC-derived group tag, role and selected native route, rereads the live proof and revalidates original owner wall/monotonic expiry before native dispatch. A timed-out read has unknown transport completion but no provider mutation and is not credited; cleanup proceeds. Binder cancellation cannot promise termination of a blocked platform Binder call; the worker is daemonized and performs read-only work. Native expiry/socket guards remain authoritative.

It compiles actual Android integration and executes current state, caller, identity/epoch/role, stale/missing/group-transition/reentry-clear, original/enabled reserve and real owner wall/monotonic expiry regressions. These are source checks, not physical qualification. APK builds/device adoption require separately reviewed exact supplier closure and parent dispatch.

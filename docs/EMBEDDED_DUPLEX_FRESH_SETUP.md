# Source-bound fresh credential setup

`source-bound-v2` is an explicit embedded duplex build selection. It requires
`ongoing-v2` and an authenticated enrollment selection containing the actual
packaged peer keys and operator. `none` is the default and adds no fresh policy
or enrollment fields to the existing finite configuration.

The builder takes `-EmbeddedDuplexFreshSetupPolicy source-bound-v2` together
with the enrollment selection path and its expected raw SHA-256. The canonical
policy and enrollment digests bind native compilation, BuildConfig, the
packaged policy asset and the existing build descriptors. The native constructor
checks its compiled selection against the typed broker configuration, actual
local signer, remote bootstrap key, route and held process capability. A
configuration field or successful policy parse grants no runtime authority.

This feature establishes fresh credentials and pair setup under the current
owned process. It does not create an independent development DATA session,
erase old runs, migrate a prior owner, or provide owner-succession capture,
commit, seal or ARM. A retained setup closure cannot bootstrap a pristine
authority owner. The independently pinned example retains its own supported
source version.

## Actual provider joins

Fresh phases use fixed native and Java callbacks on the existing serialized
command lane. Their Original, context, signed request, entered effects and
returned receipts remain bound to the same actual actor. Typed current-session
failure observations retain their original cause. A timeout, empty replacement
registry, pending Future, cancellation request or status read cannot establish
completion or permit replay.

The native constructor retains partially created broker and platform owners
until their own terminal cleanup is proved. Prepared Start reserves actual
sender, decoder, transport, display and Spatial renderer owners with their
delivery gates closed. It checks their exact readbacks before an ordinary
accepted media ticket can open delivery. Preparation metadata is not a media
Start grant. Competing Local/Peer source construction cannot bypass the actual
renderer reservation, and Stop remains available.

Ordinary local Start also accepts the same prepared incoming decoder after an
authenticated opposite-direction Start has opened its delivery gate. This is
the existing Native contract: the local preparation remains unconsumed and its
current owner, actor/config/ARM, remote decoder and connected sender must still
match. The local sender stays gated. Java uses a separate local-Start readiness
mode over the same exact status validator; initial preparation, transport
finalization and cleanup retain their closed-gate requirements.

The receiver qualification is read-only under the existing receiver lock. It
requires the same live prepared codec/worker/callback/connection, no Stop or
failure, and either the dormant closed gate or the already-requested incoming
`receiver_armed`/`receiving` state. The app additionally joins its exact retained
preparation ID and unreleased projection. Missing, foreign, failed, stopped or
locally consumed preparation remains refused. This changes no Native consume,
signature/session check, serialized DTO or media-authority grant.

`tools/checks/Test-PreparedLocalStartHost.py` executes the complete production
holder, actual ordinaryStart-to-Platform qualification call, common identity
validators and exact receiver/resource forwarding predicates with SDK/Original
resource leaves modeled. `Test-OwnedMediaWaitsHost.py -h` exposes a receiver-only
mode for the complete shared receiver and its existing wait/Stop/interrupt
controls against retained warm JVM inputs. These are source/host checks, not
evidence of an APK, device media, performance or physical cleanup result.

Fresh eligibility joins actual NeverStarted or earned normal FullyStopped
state with current process, authority, pending dispatch, cleanup replay,
physical resource and renderer facts. Peer payload custody follows real
borrowed frame roots; an inactive source slot alone is insufficient. Roots
can be reestablished only through the current typed provider and native
witness. A still-current component is preserved rather than renewed by an
observation.

An opted-in lifecycle-v4 receipt extends the actual ongoing-v3 receipt with
retained cause and lifetime custody. It is emitted only after the corresponding
typed fresh policy and source joins succeed. Normal Stop archives its exact
original projection and completed renewal custody before a subsequent fresh
phase may replace its live state. Whole-close still requires the existing
physical native, Java, display and app-fence barriers.

## Source qualification

Use `tools/Test-QuestFreshSetupSource.ps1` for the focused source checks and
`tools/checks/Test-EmbeddedDuplexFreshSetupPolicy.ps1 -Mode Full` for the actual
typed Rust projection and Java SessionInputs conformance. Retain exact source,
supplier, tool, lock and output identities with the result. Host controls
declare their modeled Android and physical leaves.

The source runner requires the installed JDK, Android SDK, Gradle and a pinned
JVM tool input spec (`-JvmInputSpecPath`). It regenerates campaign support pins
from its current compiled app and shared media classes. The prepared SDK,
renderer, transport, capture-readiness, signing, settled-custody and two-lifetime
callers execute production owners; their named host seams remain model leaves.

Compile the complete native Android target and actual Java/Kotlin app under
default finite, ongoing without fresh setup, and explicitly pinned
source-bound-v2 selections. These source checks build no APK and establish no
headset, camera, codec, LAN, performance, physical cleanup or product adoption
evidence. See [Original custody](EMBEDDED_DUPLEX_ORIGINAL_CUSTODY.md) and the
[native fencing contract](EMBEDDED_DUPLEX_R5_CONTINUITY.md).

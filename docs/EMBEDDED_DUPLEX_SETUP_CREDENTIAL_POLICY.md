# Finite bootstrap setup credential policy

Real-peer bootstrap issues fresh grant and control/runtime lease credentials from the Android owner's clock. Setup duration is an issuance policy, separate from operation-token TTL and accepted session expiry. A slow setup must not be repaired by accepting an expired credential.

The public owner build argument `-EmbeddedDuplexSetupHorizonMs 1800000` sets the scoped Gradle input and records the selected value in the build input lock, manifest and run capsule. Ambient `RUSTY_QUEST_SPATIAL_*` values are ignored and restored by the existing builder. The artifact build input `RUSTY_QUEST_SPATIAL_EMBEDDED_DUPLEX_SETUP_HORIZON_MS` selects a decimal whole-minute integer between 300000 and 3600000 milliseconds, inclusive. Omission preserves the existing 300000 millisecond policy. A controlled test build can explicitly select `1800000` (thirty minutes), allowing repeated setup and renewal qualification without consuming the original five-minute setup credential during admission. This finite test horizon is not a promise that an arbitrary delayed operation remains valid. The owning build selection must pin this environment value and the resulting APK; an ambient variable or an old APK is insufficient.

`EmbeddedDuplexSetupCredentials` validates the bounds, positive issue time and exact signed-long addition. Runtime bindings carry the exact `setup_credential_horizon_ms` for the native renewal owner policy. Real-peer inputs issue equal grant and lease expiry at issue time plus the selected horizon. Local diagnostic credentials remain fixed at five minutes. Enrollment validation, fresh-process/display/recovery guards, command lane and native runtime input validation are unchanged. Operation tokens remain capped at sixty seconds or the existing concurrent-peer one hundred twenty seconds. Native grant/lease/session expiry, current actor/source guards and renewal semantics remain mandatory. No existing credential is refreshed or extended by this change.

Successful bootstrap and later runtime-status responses expose `setup_credential_policy`, `setup_credential_horizon_ms`, `setup_credentials_issued_at_ms` and `setup_credentials_expires_at_ms`, alongside the exact runtime configuration digest. These fields report owner issuance policy, not accepted pair/media authority. They are absent when the runtime configuration is absent; Own-capture status wrapping preserves the same metadata. Readback must match the selected artifact policy and actual runtime grant/lease inputs. Host and device wall clocks are not assumed equal.

The issuance/readback slice is Java/Kotlin/Gradle packaging work and requires a fresh APK. This slice changes no Rust or JNI source. However, the existing native renewal sequence requests a five-minute strictly extending grant and outer lease; it cannot renew a longer initial setup credential during its early lifetime. A longer controlled setup artifact therefore requires a separately qualified compatible renewal/adoption owner contract before runtime selection. It is not sufficient to skip renewal or synthesize existing success receipts. Any reuse of an accepted native library must still use the existing owner build route and literal packaged-byte/provenance checks; source inspection does not qualify a new artifact or authorize installation.

## Focused source check

Run `python apps/spatial-camera-panel-android/host-tests/embedded_duplex/test_setup_credentials.py` with Java 17 and the owner's cached `org.json` dependency. It compiles the actual policy, session-input builder and runtime status class. Enrollment and Android platform facts are explicitly modeled. Controls cover selected thirty-minute grant/lease issuance, unchanged operation-token caps, local fixture closure, positive min/max horizons, invalid bounds/clock/overflow denials and status metadata retention/absence. Android compilation and installed readback remain separate artifact/device qualifications.

The packaged Java transfer keeps the exact original ten-field binding schema when the policy is absent, for default-compatible legacy inputs. When present, it admits only the one additional `setup_credential_horizon_ms` integer field with the same finite whole-minute bounds and transfers that value verbatim. Unknown fields, strings, floating-point values, nulls and out-of-bound values are rejected before native assembly.

For the actual retained-asset transfer control, set `QUESTMS_SETUP_PRODUCT_INPUT_ROOT` to a selected authenticated product-input closure. The same focused command compiles the actual `EmbeddedDuplexPackagedInputs`, loads/verifies those assets, and calls `packagedConfigRequest` with actual new thirty-minute and default five-minute session inputs plus the legacy five-minute input without the optional field. Missing fixture input skips this additional control; a supplied invalid fixture fails. Optionally set `QUESTMS_SETUP_REQUEST_OUTPUT` to an existing fresh directory to retain the exact emitted request JSON using CreateNew for an independent native assembler test. These requests model enrollment and Android platform identity and establish no live authority.
